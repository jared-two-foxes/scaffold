# Carry ticket_snapshot forward onto validate-missed and review frames

`CriterionFrame.ticket_snapshot` exists so `TICKET_VALIDATE` can reuse the
ticket text captured at push time instead of re-fetching from Linear —
essential for a ticket pushed via `--ticket-file-in` that was never
actually created in Linear. It's only ever set on the original
`origin="ticket"` frames, though. The two frame-construction sites that
generate a ticket's *later* criteria — `next_step.py`'s
`do_ticket_validate` (for `origin="validate-missed"` frames) and
`do_push_review_findings` (for `origin="review"` frames) — never set it,
so it defaults to `None`. Since `do_ticket_validate` is invoked with
`ticket_snapshot=frame.ticket_snapshot` from whichever frame was *last
popped* for that ticket, the moment that frame happens to be
validate-missed or review origin (increasingly likely the more
validation cycles a ticket goes through), the snapshot silently
disappears and the next validation cycle falls through to
`lib.fetch_ticket_text(ticket_id)` — which calls `die()` on any HTTP
error, including "this ticket doesn't exist in Linear."

## Acceptance Criteria

- [ ] `do_ticket_validate`'s `origin="validate-missed"` `CriterionFrame` construction sets `ticket_snapshot` from the function's already-resolved `ticket_content` local variable, so criteria pushed by the safety-net re-narrow carry the ticket text forward.
- [ ] `do_push_review_findings` receives the ticket's resolved content as a parameter (threaded from `do_ticket_validate`'s call site) and sets `ticket_snapshot` on each `origin="review"` `CriterionFrame` it constructs, so criteria pushed from a CHANGES REQUESTED review carry the ticket text forward too.
- [ ] A ticket seeded once via `--ticket-file-in` (never created in Linear) completes a full `TICKET_VALIDATE` cycle that finds validate-missed criteria, and a subsequent validation cycle triggered by popping one of those validate-missed criteria, without `lib.fetch_ticket_text` being called for that ticket at any point.
- [ ] `push_ticket.py --validate-only` and `--from-gap-plan` are unchanged: both continue to have no local ticket content to carry forward (by design — neither ever loads a ticket body), so `TICKET_VALIDATE` still fetches from Linear for them when no snapshot exists.

### Context

**Where the snapshot gets set today (the one working case):**
`src/ticket_pipeline/planning/frame_factory.py`'s `build_ticket_frames`
sets `ticket_snapshot=ticket_content` on every frame it builds — these
become the initial `origin="ticket"` frames. `next_step.py`'s `do_pop`
passes `frame.ticket_snapshot` (the *just-popped* frame's own snapshot)
into `do_ticket_validate`, which is why the very first validation pass
for a freshly-pushed ticket works correctly.

**Where it silently breaks:**
- `do_ticket_validate` (`next_step.py` ~287) builds `origin="validate-missed"`
  frames with no `ticket_snapshot=` argument at all — defaults to `None`
  via the dataclass. At this point in the function, `ticket_content` is
  already resolved (either from the snapshot it was given, or from a
  fetch a few lines earlier) — it just isn't threaded into the new
  frames it constructs.
- `do_push_review_findings` (`next_step.py` ~442) doesn't even receive
  `ticket_content` as a parameter — its signature is
  `(ticket_id: str, review_text: str) -> None`. Its `origin="review"`
  `CriterionFrame` construction has the same `ticket_snapshot`-less gap.

**The observed failure mode:** confirmed via `.pipeline-log.jsonl` on a
ticket pushed with `--ticket-file-in` (a synthetic slug, never created in
Linear) that went through multiple validation cycles — a `narrow` block
logged with `tokens_prompt: 3` immediately followed a state where
`_resolve_plan_file()` had already returned `None`; the ticket-fetch side
of the same failure mode is `lib.fetch_ticket_text`
(`src/ticket_pipeline/lib/pipeline_lib.py` ~830), which calls
`ticket_source.fetch_ticket(ticket_id)` against the real Linear API and
`die()`s on any `urllib.error.HTTPError` — exactly what happens when
`ticket_id` was never actually created there.

**Why the fix is narrow and mechanical:** `ticket_content` is already a
resolved local variable in `do_ticket_validate` by the time either
frame-construction site runs (`validate-missed` inline, `review` via
`do_push_review_findings`'s call site further down the same function).
This is purely a matter of passing that existing value through to the
`CriterionFrame(...)` constructors that are missing it — no new fetch,
no new state, no change to how the snapshot is captured initially.

**Explicitly unaffected:** `push_ticket.py --validate-only` calls
`lib.ensure_validating_sentinel(ticket_id)` with no snapshot argument,
by design — it's used precisely when no criteria (and thus no ticket
content) were ever loaded this run. `--from-gap-plan` similarly passes
`ticket_content=None` to `build_ticket_frames`. Both legitimately have
nothing local to carry forward, and should keep fetching from Linear
when validation runs — this ticket does not change either path.
