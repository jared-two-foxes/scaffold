# Backtick-quote file paths in Implementation Plan / plan_context entries

`lib.extract_referenced_paths` — the mechanical floor check behind
`direct.py::recheck`, `refactor.py::advance`, `manual.py`'s
manual-criterion check, and `implement.py`'s "already satisfied by a
sibling criterion" rescue — only recognizes a file path if it's
backtick-quoted (`REFERENCED_PATH_RE`/`REFERENCED_FILENAME_RE` both
require literal backtick delimiters, by design, so they don't match
stray code identifiers or prose). Nothing that actually produces a
criterion's `plan_context` guarantees this. Observed in practice: a
criterion's `plan_context` named the real, correct file
(`src/ticket_pipeline/lib/ai_client.py`) in its "Planned changes:" line,
the Implementor genuinely changed exactly that file, but
`extract_referenced_paths` found zero candidate paths (no backticks
anywhere in the criterion text or plan_context), so `recheck()` paused
with "no referenced file appears in git changes" despite the change
being correct and complete.

## Acceptance Criteria

- [ ] `plan.prompt.md`'s `## Implementation Plan` format (`- [file or component]: [one-sentence description of the change]`) instructs the model to backtick-quote the file path in every entry.
- [ ] `narrow-plan.prompt.md`'s structurally identical `## Implementation Plan` format gets the same explicit backtick-quoting instruction (today it only requires backticks for the unrelated "scoping partially-met criteria" special case, not this general entry format).
- [ ] `render_plan_context` (`src/ticket_pipeline/planning/agent_rendering.py`) backtick-quotes each `PlannedChange.path` in its "Planned changes:" rendering, consistent with how the same function already backtick-quotes `evidence.path` two lines below it.
- [ ] A test demonstrates that `lib.extract_referenced_paths` finds the path in a `plan_context` string produced by `render_plan_context` for an assessment with a `planned_changes` entry, closing the gap between the two currently-untested-together pieces.

### Context

**The incident this addresses:** criterion `` `_post_chat_completion`'s
request payload includes an explicit `max_tokens` value `` (ticket
`adhoc-truncated-response-detection`). Its `plan_context`:
```
Rationale: No max_tokens anywhere in the payload construction...
Planned changes:
- src/ticket_pipeline/lib/ai_client.py: Add module-level constant MAX_COMPLETION_TOKENS = 16384. ...
```
No backticks around the path. `direct.py::recheck`
(`src/ticket_pipeline/strategies/direct.py` ~44) does:
```python
paths = lib.extract_referenced_paths(f"{frame.criterion}\n{frame.plan_context}")
mechanically_confirmed = bool(paths) and bool(set(paths) & set(lib.git_changed_files()))
```
`extract_referenced_paths` (`src/ticket_pipeline/lib/pipeline_lib.py`
~875) requires a backtick-delimited match
(`` REFERENCED_PATH_RE = re.compile(r"`([\w./-]+/[\w.-]+\.[A-Za-z]{1,5})`") ``,
same for the bare-filename variant) — deliberately, per its own comment,
so it doesn't match stray identifiers in prose. With no backticks
anywhere in `frame.criterion` or `frame.plan_context`, `paths` is empty,
`mechanically_confirmed` short-circuits to `False`, and `recheck()`
reports "not yet verified" even though `git status` genuinely showed
`src/ticket_pipeline/lib/ai_client.py` as changed.

**Root cause — the producing side never guarantees the format the
consuming side requires:** `plan.prompt.md`'s actual template for this
section:
```
## Implementation Plan
- [file or component]: [one-sentence description of the change]
```
No backtick-quoting instruction anywhere near it.
`narrow-plan.prompt.md` mirrors the identical template and only mentions
backtick-quoting in one unrelated place — the "Scoping partially-met
criteria" section, which backtick-quotes file paths specifically when
rewriting a criterion's *visible text* to name a narrowed subset of
items, not as a rule for the general Implementation Plan entry format
either prompt actually uses.

**The agent planning strategy has the identical gap, and it's
inconsistent within its own function:**
`render_plan_context` (`src/ticket_pipeline/planning/agent_rendering.py`
~18) renders `planned_changes` without backticks:
```python
f"- {c.path}: {c.description}"
```
but renders `evidence` two lines later *with* backticks:
```python
f"- {('`' + e.path + '`') if e.path else '(repo)'}: {e.observation}"
```
Same function, same kind of field (a repository path), inconsistent
quoting — good evidence this is an oversight, not a deliberate choice.

**Worth noting, not resolving here:** `render_plan_context`'s own
docstring says *"No downstream component should parse this for
metadata"* — but `extract_referenced_paths` is exactly that, called from
four separate mechanical checks across three strategy modules. This
ticket does not attempt to resolve that tension (whether `plan_context`
should be treated as opaque prose or as semi-structured data worth
parsing) — it only ensures the one specific thing four already-existing
mechanical checks depend on (a backtick-quoted path) is actually
produced consistently, regardless of which planning strategy or prompt
generated the criterion.
